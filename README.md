## 1. 요약

**우리가 확인하려던 것.** 「원/달러는 장중에 한쪽으로 쏠렸다가 되돌아오는 일이 잦다」는 시장의 통념을, 미국달러 선물 1분봉에서 **볼린저 밴드 이탈 뒤 복귀**라는 가장 단순한 규칙으로 시험했습니다. 그리고 그 되돌림이 **거래 비용을 넘을 만큼 큰지**를 재는 데 초점을 두었습니다. 팀 탐구 주제(USD/KRW 선물을 수출 산업의 선행지표로 쓰는 대시보드)와 같은 시장이라, 이번 실행에서 쌓은 1분봉을 이후 주차 데이터로도 씁니다.

**우리가 한 것.**
1. API 명세에 맞춰 시세·주문·체결 확인·잔고 대조·기록을 하는 프로그램을 직접 작성하고, 실행과 백테스트가 **같은 판정 코드**(`engine.py`)를 쓰게 했습니다.
2. 실행 **전에** 최근 5거래일 실제 1분봉으로 숫자 근거를 재고, 규칙 변형 11개를 **설계용 3일 / 검증용 2일**로 나눠 비교한 뒤, 규칙을 바꾸지 않고 실행하기로 정했습니다(3-7절).
3. 10/27~10/30 매일 모의계좌로 실제 주문을 내며 돌렸고, 실행 중 드러난 코드 결함 3가지를 그때그때 고쳤습니다(8-1절).

**알게 된 것.**
- 신호에는 **약한 우위**가 있지만, 한 번에 먹는 폭(중심선 청산 평균 4.5틱)이 작아 **거래 비용이 결과를 정합니다** — 실행 전 백테스트(비용 0 +37,000원 ↔ 비용 1틱 −131,000원)와 실제 실행(미끄러짐 평균 0.2틱, 0틱 백테스트에 가까운 결과)이 같은 방향을 가리켰습니다.
- 되돌림 가설은 **박스권 날에는 대체로 맞고, 추세가 선 날에는 틀렸습니다** — 나흘 손실 −34,000원 중 −27,000원이 매도(27건)에서, 특히 상승 추세 날(10/28) 추세에 맞선 매도에서 났습니다.
- 손실 한도를 「닿은 뒤」가 아니라 「다음 손절을 감당 못 할 때」 막는 규칙이 추세일(10/28)에 손실을 한도 안에서 멈췄습니다.

| 프로그램이 하는 일 | 방법 | 기록 |
| --- | --- | --- |
| 시세 수신 | 현재가 `price` 를 5초마다(손절 판정), 분봉 `chart-minute` 을 봉 마감 2초 뒤(신호 판정) 조회 | `api_calls.csv`, `bars.csv` |

## 2. 실행 방법

### 2-1. 준비

```powershell
python -m pip install -r requirements.txt   # requests, matplotlib
python -m unittest discover tests           # 규칙 단위 시험 13개 (키 불필요)
```

Windows 11 에서는 Microsoft Store 의 공식 Python 3.13 을 썼습니다. `uv` 가 받아 온 파이썬은 스마트 앱 컨트롤에 막혔습니다(8-1절).

키는 환경변수 `NH_APP_KEY`·`NH_APP_SECRET` 로 줍니다(실행에 쓴 방식). `config.example.json` 을 `config.local.json` 으로 복사해 넣어도 됩니다 — 이 파일은 `.gitignore` 에 있어 올라가지 않습니다. 같은 코드를 팀원이 각자 자기 키로 돌릴 수 있습니다.

```powershell
# Windows PowerShell — 그 창에서만 유효
$env:NH_APP_KEY = "발급받은 APP Key"
$env:NH_APP_SECRET = "발급받은 APP Secret"
python run_live.py --mode paper --smoke-order --run-minutes 1
```
발급받은 접근 토큰은 `.token_cache.json` 에 만료 시각과 함께 저장해 다시 켤 때 재사용합니다(인증 호출 줄이기, 이 파일도 올리지 않음).

### 2-2. 실행 순서 (권장)

```bash
# ① 주문 API 왕복 확인: 매수 1 → 매도 1, 잔고 0 확인 후 1분 뒤 종료 (모의 09:00~15:45)
python run_live.py --mode paper --smoke-order --run-minutes 1

# ② 백테스트: 최근 5거래일 1분봉을 받아 같은 엔진으로 실행 (모의 키면 --env paper)
python backtest.py --days 5 --env paper
python backtest.py --bars-csv results/backtest_<시각>/bars_input.csv    # 저장한 봉으로 똑같이 재현

# ③ 본 실행: 09:00 전에 켜 두면 오늘 봉으로 지표를 준비하고 15:40 에 스스로 끝남
python run_live.py --mode paper --poll 5 --timeout 20

# (이번에는 쓰지 않음) 모의계좌 주문을 못 할 때의 프로그램 안 시뮬레이션: 실전 키로 시세만, 주문 없음
python run_live.py --mode sim --env real --symbol A756B000

# 요약 다시 만들기
python summarize.py results/run_paper_20261027_093818

# 여러 날 모의계좌 실행을 하나로: combined_summary.md(날짜별·시간대별) + usdkrw_1min_bars.csv(1분봉 데이터셋)
python summarize.py --combine results
```

실행이 끝나면(15:40, `--run-minutes` 경과, Ctrl+C 모두) 보유 포지션을 시장가로 정리하고, 잔고를 다시 조회해 0 인지 기록한 뒤 `summary.md` 를 만듭니다.
`--mode paper` 는 모의 환경(`--env paper`)에서만 주문하도록 막아 두었습니다. 실전 계좌로는 주문하지 않습니다.

### 2-3. 키 없이 흐름 점검 (개발용, macOS·Linux 셸 기준)

- 팀 탐구 주제(USD/KRW 선물을 수출 기업 실적의 선행지표로 쓰는 대시보드)와 같은 시장이라, 이번 실행에서 쌓는 1분봉·체결 데이터를 이후 주차에 그대로 씁니다.
- 1주차에 미국달러 선물을 다뤄 종목 특성(실물인수도, 월물 구조)을 이미 정리해 두었습니다.
- **월물:** 10월물은 10/19 에 만기가 지나 과제 기간(10/26~10/30)의 근월물은 11월물입니다. 만기까지 3주 가까이 남아 기간 안에 월물 교체가 없습니다.

### 3-2. 전략을 고른 까닭

| 후보 | 판단 |
| --- | --- |
| **볼린저 밴드 이탈 뒤 복귀 (채택)** | 원/달러는 장중에 수출입 결제 수요와 외환당국의 미세조정 경계감으로 짧은 구간의 쏠림이 되돌려지는 일이 잦다는 시각이 있습니다. 이 가설을 1분봉에서 직접 시험해 볼 수 있는 가장 단순한 규칙입니다. 아래 「시장 배경」 참고. |
| 이동평균 교차 | 샘플이 이미 다룬 전략이고, 변동이 작은 원/달러 1분봉에서는 교차가 잦아 손절이 쌓이기 쉽습니다. |
| 변동성 돌파 | 하루 한 번 진입이 보통이라 한 주 실행으로는 표본이 너무 적습니다. |
| 시가 범위 돌파 | 거래시간이 08:45 시작인데 모의계좌는 09:00 시작이라, 시가 범위를 실행 안에서 온전히 관측하기 어렵습니다. |

「밴드에 닿으면 바로 반대로」가 아니라 **밖으로 나갔다가 다시 들어온 봉을 확인한 뒤** 진입합니다. 쏠림이 계속되는 동안 미리 반대로 서는 것을 피하기 위해서입니다.

**시장 배경 — 왜 원/달러에서 되돌림을 기대했나, 그리고 언제 깨지나**

- **실수요 주문이 양쪽에서 들어옵니다.** 수출업체는 받은 달러를 원화로 바꾸며 달러를 팔고(네고), 수입업체는 결제를 위해 달러를 삽니다. 한쪽으로 쏠린 가격에 반대쪽 실수요가 들어오면 짧은 되돌림이 생길 수 있다는 것이 가설의 바탕입니다.
- **월말에는 한쪽이 강해집니다.** 시황 기사에서 월말 수출업체 네고 물량이 원/달러를 끌어내린다는 설명이 반복해서 나옵니다(예: 2026-08-31 장초반 1,380원 → 오후 월말 네고로 1,368.6원 마감 — KB Think 환율 전망 2026-09-01). 과제 기간(10/26~10/30)이 월말이라, 한 방향 수급이 되돌림을 누를 수 있다는 점을 실행 전에 알고 시작했습니다.
- **장중 리듬:** 개장 직후는 밤사이 해외 움직임이 반영되어 거칠고, 점심 무렵은 잔잔합니다. 실행 전 5일 분봉의 밴드폭 중앙값이 09시 22.9틱 → 13시 8.9틱이었습니다(3-7절).
- **되돌림이 깨지는 날:** 뚜렷한 재료로 한 방향 추세가 나면 「복귀」 뒤에도 다시 밀립니다. 10/28 이 그런 날이었습니다(6-3절 2일차).

### 3-3. 매매 규칙

| 구분 | 조건 |
| --- | --- |
| 지표 | 최근 20개 1분봉 종가의 평균(중심선) ± 2.0 × 표준편차 |
| 매수 진입 | 직전 봉 종가 < 직전 하단밴드 **그리고** 이번 봉 종가 ≥ 이번 하단밴드 |
| 매도 진입 | 직전 봉 종가 > 직전 상단밴드 **그리고** 이번 봉 종가 ≤ 이번 상단밴드 |
| 중심선 청산 (익절 목표) | 봉 마감 종가가 중심선에 닿음(매수 ≥ / 매도 ≤) — 중심선이 움직여 손실로 끝날 수도 있음 |
| 손절 | 진입 **체결가**에서 불리하게 5틱(0.5원) — 현재가 조회 때마다 판정(10/27 부터 5초 간격) |
| 시간 청산 | 보유 30봉(30분) 경과 |
| 진입 필터 | 밴드폭(상단−하단) ≥ 8틱 · 진입 시간 09:05~15:15 · 손절 뒤 3봉 대기 · 하루 20회 · 남은 손실 한도 ≥ 1회 손절액 |
| 장 마감 | 15:30 부터 보유 전량 시장가 정리 |
| 주문 | 시장가(`ord_tp_cd=2`, 가격 0) · FAS · 1계약 · 보유 중 추가 진입 없음 |
| 일일 손실 한도 | 30,000원 — **남은 한도가 1회 손절액(5,000원)보다 작아지면** 그날 신규 진입 중지 |

판정은 봉이 **마감된 뒤 한 번만** 합니다. 진행 중인 봉으로 판정하면 한 봉 안에서 신호가 켜졌다 꺼질 수 있고, 백테스트(마감 종가 기준)와 조건이 달라지기 때문입니다.

### 3-4. 값마다 그렇게 정한 까닭

| 규칙 | 값 | 까닭 |
| --- | --- | --- |
| 20봉 · 2.0σ | 표준값 | **최적화하지 않았습니다.** 지난 봉에 맞춰 고르면 그 기간에만 맞는 값이 됩니다. 기준점을 먼저 만들고 변형은 같은 봉으로 비교합니다(9절). |

| 시장가 FAS | — | 신호 직후 체결되어야 규칙을 검증할 수 있습니다. 1계약이라 FAS/FOK 차이는 없습니다. |

### 3-5. 미리 알고 있는 약점

- 큰 지표 발표나 외국인 대량 매매로 **한 방향 추세가 나는 날**에는 「복귀」 신호 뒤에도 다시 밴드를 뚫고 나가 손절이 쌓입니다. 손절 뒤 대기와 일일 한도로 크기를 제한하고, 그 크기를 기록으로 잽니다.
- 원/달러 1분봉은 변동이 작아 밴드폭 필터에 걸려 **신호가 적은 날**이 있을 수 있습니다. 막힌 신호도 `signals.csv` 에 남겨 필터가 얼마나 걸렀는지 셉니다.
- 손절은 현재가 조회 간격(기본 2초, 10/27 부터 5초)마다 판정하므로, 그 사이에 급하게 움직이면 손절가보다 불리하게 체결되거나 짧은 급등락을 놓칠 수 있습니다.
- **손익 구조가 불리할 것으로 예상했습니다(실행 전).** 진입은 밴드 안쪽(복귀 확인 뒤), 청산 목표는 중심선이라 이기는 거래의 기대 폭은 대략 2~3틱, 지는 거래는 손절 5틱 + 미끄러짐 약 1틱으로 보아 손익분기 승률을 65% 안팎으로 잡았습니다. 실제로는 중심선 청산이 평균 4.5틱으로 예상보다 커서 실측 손익분기는 약 48%였고, 실제 승률은 41%였습니다(7-1절).

- **과최적화 사례:** 손절 7틱(V5)은 비용 0 기준으로 설계 구간에서 11개 중 가장 좋았지만(+43,000원) 검증 구간에서 −11,000원으로 뒤집혔습니다. 앞 3일만 보고 골랐다면 잘못 채택했을 변형입니다.
- 3분봉·손절 8틱·밴드폭 12틱은 손실을 가장 줄였지만(5일 22건 −25,000원) 같은 5일로 고른 값이고 표본이 작아 결론으로 삼지 않았습니다.

**결정:** 본 실행은 **미리 정한 기준 규칙(V0)을 바꾸지 않고** 돌립니다. 5일치로 고른 값으로 규칙을 바꾸면 지난 데이터에 맞춘 것과 구분할 수 없기 때문입니다. 실제 실행에서도 「신호의 우위보다 거래 비용이 크다」가 다시 나타나는지를 7절에서 확인합니다. 선택 규칙들은 `engine.py` 에 기본값 꺼짐으로 남겨 두어 이후 비교에 씁니다.

### 4-4. API 를 쓸 때 지킨 것

- **성공 판정:** HTTP 200 이어도 본문의 `errorCode`(정상코드 제외)나 `msg_cd` 가 비어 있지 않으면 실패로 봅니다. 주문 성공 응답은 `msg_cd`·`msg_cntn` 이 빈 문자열입니다.
- **토큰:** 401 이나 `EGW05x` 를 받으면 토큰을 한 번만 새로 받아 재시도합니다. 401 은 처리 전 거절이라 주문도 중복되지 않습니다.
- **주문 재전송 금지:** 주문 응답을 못 받으면(시간 초과) 다시 보내지 않고 주문내역에서 그 주문을 찾습니다. 없으면 실패로 기록하고 넘어갑니다.
- **호출 제한:** 시세·계좌 초당 10건, 주문 5건 등급에 맞춰 등급마다 최소 간격을 둡니다. 평소 사용량은 초당 1건 안팎입니다.
- **분봉 해석:** 응답은 최신 봉이 먼저 오고 `exch_tm` 은 봉 **시작** 시각입니다. 가장 최근 줄은 진행 중인 봉이라 `시작 + 1분 ≤ 지금` 인 봉만 씁니다. 봉이 건너뛰면 `gap` 사건으로 남깁니다.
- **연속 오류:** API 오류가 이어지면 2초씩 늘려 기다리고(최대 30초), 20회 연속이면 실행을 멈추고 포지션을 정리합니다.

### 7-2. 코드 버전과 앱 버전 비교

같은 전략을 NH FUTURES API 앱의 전략주문 편집기로도 옮겼습니다(`app_strategy/strategy.json`, 앱 검사기 문제 0건). 앱 편집기로는 넣을 수 없는 규칙이 있어, 두 버전의 차이가 곧 **그 규칙들의 효과**를 재는 비교가 됩니다.

| 규칙 | 코드(`engine.py`) | 앱 전략주문 |
| --- | --- | --- |
| 밴드폭 ≥ 8틱일 때만 진입 | 있음 | **없음** — 조건에 「상단 − 하단」 같은 계산값을 쓸 수 없음 |

| 청산 뒤 3봉 대기 | 손절 뒤에만 | 모든 청산 뒤 |
| 돌파 판정 경계 | 직전 < 밴드, 이번 ≥ 밴드 | 직전 ≤ 밴드, 이번 > 밴드 (종가가 밴드와 같을 때만 갈림) |

| 기준 봉 / 판정 | 1분봉 / 마감 | 1분봉 / 마감 |

이번 제출에서는 앱 「전략 검증」(앱 시뮬레이션)을 코드 실행과 나란히 돌리지 않아, 규칙 차이까지만 정리합니다. 같은 기간 두 버전의 결과 비교는 9절 향후 계획에 넣었습니다.

### 7-3. 백테스트 가정과 한계 (`backtest.py`)

- 신호·청산은 다음 봉 시가에, 불리한 쪽으로 1틱 미끄러져 체결된다고 봅니다.
- 손절은 봉의 저가(매수)·고가(매도)가 손절가에 닿으면 손절가에서, 시가가 이미 넘었으면 시가에서 체결 − 1틱.

- 그날 마지막 봉까지 보유가 남으면 마지막 종가로 정리합니다. 수수료 0원.
