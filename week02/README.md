## 1. 과제 요약

국내 선물 1종목(미국달러 선물)에 대해 규칙 기반 전략을 직접 코드로 구현하고, 모의환경에서 실행해 신호·주문·체결·손익을 모두 파일로 남긴 뒤 분석합니다.
평가 관점은 수익이 아니라 「계획한 대로 돌았는가 · API 를 바르게 썼는가 · 결과를 설명할 수 있는가」입니다.

| 필수 요소 | 이 제출에서 한 것 | 근거 |
| --- | --- | --- |
| 시세 수신 | 현재가(`price`)를 2초마다, 분봉(`chart-minute`)을 봉 마감 2초 뒤 조회 | `api_calls.csv` |
| 신호 판정 | 1분봉 마감 때 밴드 이탈 뒤 복귀를 판정, 막힌 신호도 이유와 함께 기록 | `signals.csv` |
| 주문 처리 | 시장가 FAS 1계약 → 주문내역으로 체결 확인 → 미체결은 취소 → 잔고 대조 | `orders.csv`·`fills.csv` |
| 위험 관리 | 손절 5틱, 시간 청산 30봉, 일일 손실 한도(사전 차단), 진입 시간대, 15:30 정리 | `strategy_config.json` |
| 실행 기록 | 사건 로그 + CSV 7종 + 실행 메타 | `results/<run_id>/` |

## 2. 실행 방법

### 2-1. 준비

```bash
pip install -r requirements.txt
cp config.example.json config.local.json   # 키 입력. config.local.json 은 .gitignore 에 있어 올라가지 않음
python -m unittest discover tests          # 규칙 단위 시험 (키 불필요)
```

`config.local.json` 대신 환경변수 `NH_APP_KEY`, `NH_APP_SECRET`, `NH_ENV`(paper/real) 로도 줄 수 있습니다. 같은 코드를 팀원이 각자 자기 키로 돌릴 수 있고, 키는 GitHub 에 올라가지 않습니다.

```powershell
# Windows PowerShell — 그 창에서만 유효
$env:NH_APP_KEY = "발급받은 APP Key"
$env:NH_APP_SECRET = "발급받은 APP Secret"
python run_live.py --mode paper --smoke-order --run-minutes 1
```
발급받은 접근 토큰은 `.token_cache.json` 에 만료 시각과 함께 저장해 다시 켤 때 재사용합니다(인증 호출 줄이기, 이 파일도 올리지 않음).

### 2-2. 실행 순서 (권장)

```bash
# ① 주문 API 왕복 확인: 매수 1 → 매도 1, 잔고 0 확인 후 1분 뒤 종료 (모의 09:00~15:45)
python run_live.py --mode paper --smoke-order --run-minutes 1

# ② 백테스트: 최근 5거래일 1분봉을 받아 같은 엔진으로 실행 (실전 키로 시세 조회)
python backtest.py --days 5 --env real
python backtest.py --bars-csv results/backtest_<시각>/bars_input.csv    # 저장한 봉으로 똑같이 재현

# ③ 본 실행: 09:00 전에 켜 두면 오늘 봉으로 지표를 준비하고 15:40 에 스스로 끝남
python run_live.py --mode paper --symbol A756B000

# (모의계좌 주문을 못 하는 경우) 프로그램 안 시뮬레이션: 실전 키로 시세만, 주문 없음
python run_live.py --mode sim --env real --symbol A756B000

# 요약 다시 만들기
python summarize.py results/run_paper_20261027_085912

# 여러 날 모의계좌 실행을 하나로: combined_summary.md(날짜별·시간대별) + usdkrw_1min_bars.csv(1분봉 데이터셋)
python summarize.py --combine results
```

실행이 끝나면(15:40, `--run-minutes` 경과, Ctrl+C 모두) 보유 포지션을 시장가로 정리하고, 잔고를 다시 조회해 0 인지 기록한 뒤 `summary.md` 를 만듭니다.
`--mode paper` 는 모의 환경(`--env paper`)에서만 주문하도록 막아 두었습니다. 실전 계좌로는 주문하지 않습니다.

### 2-3. 키 없이 흐름 점검

```bash
python tests/mock_server.py --port 8765 --reject-first &      # 첫 조회를 401 로 거절 → 토큰 재발급 경로까지 시험

```

가짜 서버의 가격은 지어낸 값입니다. 이 점검 결과는 보고서의 결과로 쓰지 않습니다.

- 1주차에 미국달러 선물을 다뤄 종목 특성(실물인수도, 월물 구조)을 이미 정리해 두었습니다.
- **월물:** 10월물은 10/19 에 만기가 지나 과제 기간(10/26~10/30)의 근월물은 11월물입니다. 만기까지 3주 가까이 남아 기간 안에 월물 교체가 없습니다.

### 3-2. 전략을 고른 까닭

| 후보 | 판단 |
| --- | --- |
| **볼린저 밴드 이탈 뒤 복귀 (채택)** | 원/달러는 장중에 수출입 결제 수요와 외환당국의 미세조정 경계감으로 짧은 구간의 쏠림이 되돌려지는 일이 잦다는 시각이 있습니다. 이 가설을 1분봉에서 직접 시험해 볼 수 있는 가장 단순한 규칙입니다. |
| 이동평균 교차 | 샘플이 이미 다룬 전략이고, 변동이 작은 원/달러 1분봉에서는 교차가 잦아 손절이 쌓이기 쉽습니다. |
| 변동성 돌파 | 하루 한 번 진입이 보통이라 한 주 실행으로는 표본이 너무 적습니다. |
| 시가 범위 돌파 | 거래시간이 08:45 시작인데 모의계좌는 09:00 시작이라, 시가 범위를 실행 안에서 온전히 관측하기 어렵습니다. |

「밴드에 닿으면 바로 반대로」가 아니라 **밖으로 나갔다가 다시 들어온 봉을 확인한 뒤** 진입합니다. 쏠림이 계속되는 동안 미리 반대로 서는 것을 피하기 위해서입니다.

### 3-3. 매매 규칙

| 구분 | 조건 |
| --- | --- |
| 지표 | 최근 20개 1분봉 종가의 평균(중심선) ± 2.0 × 표준편차 |
| 매수 진입 | 직전 봉 종가 < 직전 하단밴드 **그리고** 이번 봉 종가 ≥ 이번 하단밴드 |
| 매도 진입 | 직전 봉 종가 > 직전 상단밴드 **그리고** 이번 봉 종가 ≤ 이번 상단밴드 |
| 익절 | 봉 마감 종가가 중심선에 닿음(매수 ≥ / 매도 ≤) |
| 손절 | 진입 **체결가**에서 불리하게 5틱(0.5원) — 2초마다 현재가로 판정 |
| 시간 청산 | 보유 30봉(30분) 경과 |
| 진입 필터 | 밴드폭(상단−하단) ≥ 8틱 · 진입 시간 09:05~15:15 · 손절 뒤 3봉 대기 · 하루 20회 · 남은 손실 한도 ≥ 1회 손절액 |
| 장 마감 | 15:30 부터 보유 전량 시장가 정리 |
| 주문 | 시장가(`ord_tp_cd=2`, 가격 0) · FAS · 1계약 · 보유 중 추가 진입 없음 |
| 일일 손실 한도 | 30,000원 — 닿으면 그날 신규 진입 중지 |

판정은 봉이 **마감된 뒤 한 번만** 합니다. 진행 중인 봉으로 판정하면 한 봉 안에서 신호가 켜졌다 꺼질 수 있고, 백테스트(마감 종가 기준)와 조건이 달라지기 때문입니다.

### 3-4. 값마다 그렇게 정한 까닭

| 규칙 | 값 | 까닭 |
| --- | --- | --- |
| 20봉 · 2.0σ | 표준값 | **최적화하지 않았습니다.** 지난 봉에 맞춰 고르면 그 기간에만 맞는 값이 됩니다. 기준점을 먼저 만들고 변형은 같은 봉으로 비교합니다(9절). |
| 밴드폭 ≥ 8틱 | 0.8원 | 진입은 밴드 근처, 익절은 중심선이라 먹을 폭은 대략 밴드폭의 절반(≥4틱)입니다. 왕복 미끄러짐을 2틱으로 보면 그보다 좁은 밴드에서는 이겨도 남는 것이 없습니다. |
| 손절 5틱 | 5,000원 | 손절 + 미끄러짐 1틱 = 6,000원. 일일 한도 30,000원의 1/5. |
| 시간 청산 30봉 | 30분 | 평균회귀가 30분 안에 일어나지 않으면 가설이 틀린 국면으로 보고 나옵니다. |
| 손절 뒤 3봉 대기 | 3분 | 한 방향 쏠림에서 같은 신호로 연속 손절하는 것을 줄입니다. |
| 남은 한도 사전 차단 | — | 샘플 보고서에서 「한도 직전에 들어간 거래 하나만큼 한도를 넘는」 문제가 확인되어, 남은 한도가 1회 손절액보다 작으면 진입 자체를 막습니다. |
| 09:05~15:15 · 15:30 정리 | — | 모의 09:00 개장 직후의 몇 분은 거르고, 15:35 마감 단일가 전에 정리합니다. |
| 시장가 FAS | — | 신호 직후 체결되어야 규칙을 검증할 수 있습니다. 1계약이라 FAS/FOK 차이는 없습니다. |

### 3-5. 미리 알고 있는 약점

- 큰 지표 발표나 외국인 대량 매매로 **한 방향 추세가 나는 날**에는 「복귀」 신호 뒤에도 다시 밴드를 뚫고 나가 손절이 쌓입니다. 손절 뒤 대기와 일일 한도로 크기를 제한하고, 그 크기를 기록으로 잽니다.
- 원/달러 1분봉은 변동이 작아 밴드폭 필터에 걸려 **신호가 적은 날**이 있을 수 있습니다. 막힌 신호도 `signals.csv` 에 남겨 필터가 얼마나 걸렀는지 셉니다.
- 손절은 2초 간격의 현재가로 판정하므로, 그 사이에 급하게 움직이면 손절가보다 불리하게 체결될 수 있습니다.
- **손익 구조가 불리합니다.** 진입은 밴드 안쪽(복귀 확인 뒤), 익절은 중심선이라 이기는 거래의 기대 폭은 대략 2~3틱인데, 지는 거래는 손절 5틱 + 미끄러짐 약 1틱입니다. 손익분기 승률이 약 65% 안팎으로 높아, 평균회귀가 「자주」 맞는 것만으로는 부족하고 「아주 자주」 맞아야 합니다. 이 비율이 실제로 어떻게 나왔는지를 7절에서 잽니다.

### 3-6. 검증할 가설

이 실행은 수익을 노리기보다 아래 두 가설을 기록으로 확인하는 실험입니다.

| 가설 | 확인 방법 (기록) |
| --- | --- |
| **H1. 원/달러 선물은 1분봉에서 밴드 밖으로 쏠린 뒤 중심선으로 되돌아오는 일이 잦다** | 익절(중심선 도달) 비율 대 손절·시간 청산 비율 (`trades.csv` 의 `exit_reason`) |

### 4-3. API 를 쓸 때 지킨 것

- **성공 판정:** HTTP 200 이어도 본문의 `errorCode`(정상코드 제외)나 `msg_cd` 가 비어 있지 않으면 실패로 봅니다. 주문 성공 응답은 `msg_cd`·`msg_cntn` 이 빈 문자열입니다.
- **토큰:** 401 이나 `EGW05x` 를 받으면 토큰을 한 번만 새로 받아 재시도합니다. 401 은 처리 전 거절이라 주문도 중복되지 않습니다.
- **주문 재전송 금지:** 주문 응답을 못 받으면(시간 초과) 다시 보내지 않고 주문내역에서 그 주문을 찾습니다. 없으면 실패로 기록하고 넘어갑니다.
- **호출 제한:** 시세·계좌 초당 10건, 주문 5건 등급에 맞춰 등급마다 최소 간격을 둡니다. 평소 사용량은 초당 1건 안팎입니다.
- **분봉 해석:** 응답은 최신 봉이 먼저 오고 `exch_tm` 은 봉 **시작** 시각입니다. 가장 최근 줄은 진행 중인 봉이라 `시작 + 1분 ≤ 지금` 인 봉만 씁니다. 봉이 건너뛰면 `gap` 사건으로 남깁니다.
- **연속 오류:** API 오류가 이어지면 2초씩 늘려 기다리고(최대 30초), 20회 연속이면 실행을 멈추고 포지션을 정리합니다.

## 7. 결과 해석

⟪실행 뒤 작성. 아래 질문에 기록으로 답합니다.⟫

1. **규칙대로 돌았는가** — `signals.csv` 의 신호 봉마다 직전·이번 종가와 밴드 값을 보고 조건이 참인지 대조. 진입 체결이 신호 봉 마감 뒤 몇 초 안에 났는지(`orders.csv` 의 `intent_ts`↔`sent_ts`).
2. **어디서 벌고 잃었는가** — 청산 사유별 손익. 익절이 중심선까지 평균 몇 틱이었는지, 손절이 5틱+미끄러짐 몇 틱이었는지.
3. **H1 — 장중 되돌림이 맞았는가** — 익절 대 손절·시간 청산 비율, 실제 손익분기 승률과의 비교. 손절이 몰린 날·구간이 추세 구간이었는지 `chart.png` 로 확인.
4. **H2 — 시간대별로 달랐는가** — `combined_summary.md` 의 시간대별 표로 오전·오후, 시(hour)별 승률·손익과 평균 밴드폭을 비교. 밴드폭이 좁아 신호가 막힌 시간대가 어디였는지도 같이 봄.
5. **필터가 얼마나 걸렀는가** — 막힌 신호의 이유별 건수(특히 밴드폭 8틱).
6. **백테스트와 실행의 차이** — 같은 날 봉으로 백테스트를 다시 돌려(`--bars-csv`) 거래 단위로 비교. 차이의 원인(진입가 = 다음 봉 시가 가정 vs 실제 시장가, 손절 판정 간격)을 적음.
7. 표본이 적으면 승률·손익으로 전략의 좋고 나쁨을 말하지 않고, 그 한계를 적습니다.

### 7-1. 백테스트 가정과 한계 (`backtest.py`)

- 신호·청산은 다음 봉 시가에, 불리한 쪽으로 1틱 미끄러져 체결된다고 봅니다.
- 손절은 봉의 저가(매수)·고가(매도)가 손절가에 닿으면 손절가에서, 시가가 이미 넘었으면 시가에서 체결 − 1틱.
- 익절은 봉 마감 판정이라 같은 봉 안에서 손절·익절이 충돌하지 않습니다.
- 그날 마지막 봉까지 보유가 남으면 마지막 종가로 정리합니다. 수수료 0원.

## 10. 팀 탐구 주제와의 연결

우리 팀(리드랙)의 탐구 주제는 **USD/KRW 통화선물을 반도체·방산 등 수출 산업 실적의 선행지표로 활용하는 대시보드**입니다. 2주차 실행은 그 데이터 기반을 쌓는 첫 단계이기도 합니다.

| 2주차에서 나오는 것 | 탐구 주제에서 쓰는 곳 |
| --- | --- |
| `results/usdkrw_1min_bars.csv` — 실행 기간 미국달러 선물 1분봉(`summarize.py --combine` 이 실행마다 모아 중복 제거) | 일·주 단위로 묶어 환율 수준·변동성 지표를 만들고, 수출 기업 분기 실적과 시차를 두고 비교 |

2주차 데이터는 한 주 남짓이라 선행지표 여부를 판단할 수준은 아닙니다. 여기서는 수집·정리 경로를 만들어 두는 것까지를 목표로 합니다.
