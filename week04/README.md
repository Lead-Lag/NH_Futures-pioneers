## 1. 요약

**확인하려던 것.** 같은 반도체 업종인 두 회사 선물의 1분 단위 상대가격이 평소 관계에서 크게 벗어났을 때 **되돌아오는가**, 그리고 그 되돌림이 **두 다리 × 진입·청산 네 번의 거래 비용을 넘는가**. 동시에 이번 주 과제의 핵심인 **두 주문을 하나의 거래로 관리**(한쪽만 체결되는 상황 처리)를 실제 모의계좌에서 검증합니다.

**한 것.**
1. 실행 **전에** 9거래일 1분봉으로 유동성·관계·괴리 빈도·비용을 재고, 설계용 5일 / 검증용 4일로 나눠 규칙을 정한 뒤 바꾸지 않기로 했습니다(3-7절).
2. 두 다리 주문을 상태로 관리하는 실행 코드를 작성하고, 가짜 서버로 「둘째 다리 미체결·부분체결·첫 다리 거부·취소 직전 체결·나뉜 체결·응답 시간 초과·토큰 거절·실시간 끊김」을 일부러 만들어 시험했습니다.
3. 운영진 안내에 따라 시세를 **REST → WebSocket** 구조로 바꿨습니다(4절).

**알게 된 것(11/11 기준).**
- **삼성 호가 한 칸이 되돌림보다 큽니다.** 삼성 선물은 20만원 이상에서 호가단위가 500원(가격의 약 24bp)으로, 스프레드의 1분 표준편차(약 18bp)보다 큽니다. 1분봉 종가가 매수·매도호가 사이를 한 번 오가기만 해도 z 가 1σ 넘게 움직입니다.
- **과거 24거래일 워크포워드(3-8절):** 판정 봉 종가에 바로 체결·비용 0 이면 하루 평균 **+44.5만원**(95% 구간 +28.7만~+59.8만). 그러나 실제 호가단위로 **다리마다 0.5틱만 들어도 −11.0만원**(−18.0만~−4.0만), 1틱이면 −39.8만원. 체결을 1분 늦추면 비용 0 에서도 +0.9만원(0 포함). → **H1 은 조건부, H2 는 아니오.**
- **본 실행 11/11(6-3·7절):** 7건 **−38만원**. 하지만 **판정 가격 기준으로는 +31만원**이었고, 체결 비용 69만원(삼성 평균 1.0틱·하이닉스 0.5틱)이 결과를 뒤집었습니다. 과거 검증에 이 실측 비용을 넣은 예상(하루 −36.8만원)과 거의 같아, **검증 모형이 실제 결과를 잘 설명**합니다.
- **H3 는 예.** 14개 페어 주문 모두 `COMPLETE`, 한쪽만 체결된 시간 중앙 205ms(최대 550ms), 체결 확인 28건 모두 WebSocket 주문/체결 통보(O1). 노트북 절전으로 실행이 3번(최장 36분) 멈췄지만 밀린 봉으로는 주문하지 않고 실시간을 다시 연결했습니다.
- 11/10 첫 실거래의 「삼성이 200,000원으로 잠깐 떨어졌다가 200,500원으로 복귀」는 바로 **호가 한 칸(500원) 튕김**이었습니다(판정 가격 +5만원 → 체결가 −4만원).

| 종목코드 | `A116C000` (12월물) | `A506C000` (12월물) | 종목 마스터 `stk_fut_opt.mst` (`pair_analyze.py find`) |
| 승수 / 호가단위 | 10주 / **20만원 미만 100원 · 20만원 이상 500원**(약 24bp) | 10주 / 1,000원 (약 8bp) | 마스터 `ctrt_size` · 분봉 최소 가격 간격 |

**12월물을 고른 이유.** 주식선물 최종거래일은 결제월 둘째 목요일이라 11월물은 **11/12(실행 주간)에 만기**입니다. 11월물이 지금은 더 활발하지만(체결 있는 분 92~99%), 12월물도 체결 있는 분이 가장 낮은 날 79%·두 종목이 같은 분에 함께 체결된 비율 86%로 충분해 만기 교체 없이 12월물로 실행합니다.

**품목별세부정보에 주식선물 줄이 없습니다.** 2주차처럼 `product-detail` 로 틱·증거금을 읽을 수 없어, 승수는 종목 마스터에서, 호가단위는 분봉에서 확인해 설정값으로 넣었습니다. **처음에는 분봉에서 본 100원 하나만 넣었다가**, 11/11 실행 기록(20만원 위에서 체결가가 500원 단위)으로 가격별 호가단위가 있음을 확인하고 KRX 호가단위표(`pair_engine.tick_size`)로 고쳤습니다.

### 3-2. 왜 이 페어인가

| 후보 | 판단 |
| --- | --- |
| **삼성전자–SK하이닉스 주식선물 (채택)** | 두 레그 주문 관리라는 과제 핵심을 그대로 다루고, 반도체라 팀 탐구 주제(수출 산업)와 이어짐. 두 종목 모두 주식선물 중 유동성이 높은 편. 선물이라 매도 다리를 공매도 제약 없이 잡을 수 있음 |
| 미니코스피200–코스피200 | 같은 지수라 수렴 근거는 가장 확실하나 가격 차가 거의 늘 1~2틱 안이라 기회가 드묾 |
| 삼성 11월–12월물 캘린더 | 보유비용이라는 기준가가 있으나 11월물 만기(11/12)로 실행 가능일이 하루뿐 |
| SGX 원달러–국내 미국달러 | 국내·해외 두 계좌와 시간대를 함께 다뤄야 해 이번 주 일정에 무거움 |

**실제로 괴리가 커졌던 때.** 2024-05-24 삼성 HBM 엔비디아 테스트 관련 보도(삼성 −3.1% · 하이닉스 −0.7%), 2026-08-06 솔리다임 상장설(하이닉스 하루 −10.37%), 2026-09-21~10-21 같은 하락장에서 삼성 −14.4% · 하이닉스 −30.3%(외국인 하이닉스 18거래일 연속 순매도). **큰 괴리는 대부분 회사 고유 뉴스라 잘 되돌아오지 않습니다.** 이 전략이 노리는 것은 장중 몇 분~수십 분 안에 풀리는 작은 쏠림이고, 큰 괴리는 손절 규칙으로 막아야 하는 위험입니다.

### 3-3. 매매 규칙

| 구분 | 조건 |
| --- | --- |
| 스프레드 | s = ln(삼성) − β·ln(하이닉스), **β = 0.59** (실행 전 9일 1분 수익률 회귀, 고정) |
| z | (s − 최근 40봉 평균) ÷ 최근 40봉 표준편차 — 하루 안에서만(09:00 봉부터) |
| 진입 | z 가 +2 를 위로 넘는 봉 → **스프레드 매도**(삼성 매도 10 · 하이닉스 매수 1) / −2 를 아래로 → **스프레드 매수**(반대) |
| 진입 조건 | 그 분에 **두 종목 모두 체결**이 있었을 것(한쪽 가격이 멈춰 생긴 가짜 괴리 방지) · 진입 09:10~15:00 · 손절 뒤 3봉 대기 · 하루 20회 · 남은 손실한도 ≥ 1회 손절액 · (11/11 추가) z 계산 창 40봉 중 두 종목 모두 체결된 봉 ≥ 80% |
| 수렴 청산 | \|z\| ≤ 0.5 |
| 손절 | z 가 진입 방향으로 ±3.5 (봉 마감) **또는** 두 다리 합산 평가손실 ≥ 15만원 (실시간 체결가로 수시) |
| 시간 청산 | 보유 60봉 |
| 장 마감 | 15:15 전량 정리 (현물 15:30 마감 전) |
| 주문 | 시장가 FAS. 하이닉스(1계약) 먼저 → 체결 확인 → 삼성(10계약) |
| 일일 손실 한도 | 50만원 — 남은 한도가 1회 손절액(15만원)보다 작으면 신규 진입 중지 |

### 3-4. 값마다 그렇게 정한 이유

| 규칙 | 값 | 이유 |
| --- | --- | --- |
| 로그 가격·수익률 β | 0.59 | 두 종목은 가격 수준·변동성이 크게 달라 가격 수준 회귀는 며칠 추세만으로 그럴듯한 β 가 나옴(가짜 회귀). 수익률 β 는 「하이닉스 1% → 삼성 0.59%」로 해석이 쉽고, 계약 수는 명목금액으로 맞춤 |
| rolling 40봉 z | 40 | 고정 평균(fixed)은 날마다 스프레드 수준이 옮겨 가 하루 0.6번만 신호, 반감기 372분 → 쓸 수 없음(3-7절). **최적화하지 않은 출발값** |

### 3-5. 미리 알고 있는 약점

- **회사 고유 뉴스**(HBM 수주·자회사 상장 등)로 괴리가 계속 벌어지면 수렴하지 않고 손절됨.
- **rolling 평균의 「따라오는 수렴」**: 가격 관계가 돌아오지 않아도 평균이 따라와 z 가 0.5 안에 들면 청산 → 「수렴 청산인데 손실」이 생김(2주차 중심선 청산과 같은 성질, 11/10 첫 거래).
- **비용**: 시장가 4번 = 다리마다 약 1틱. 삼성은 20만원 이상에서 1틱이 500원(약 24bp)이라 수렴 폭(약 21bp)보다 큼(11/11 정정, 3-8절).
- **판정과 주문 사이의 지연**: 1분봉 마감 뒤 주문하므로 몇 초 사이 풀리는 괴리는 놓침.
- **한쪽만 체결**: 두 주문은 원자적으로 함께 체결되지 않음 → 5절의 상태 관리로 대응.

**체결 지연 점검 — 이 이익은 잡을 수 있는 것인가.** 위 표는 「판정한 봉의 종가에 바로 체결」을 가정합니다. 그런데 1분봉 종가는 그 분의 마지막 체결가라 호가 차(1틱) 안에서 매수호가·매도호가 사이를 오가고, 신호는 대개 가격이 한쪽 끝에 찍힌 순간 납니다. 그래서 체결을 N봉 뒤 종가로 미뤄 같은 24일을 다시 돌렸습니다(`--delays 0,1,2`).

- **H2 는 아니오.** 판정 봉 종가에 바로 체결된다는 가장 유리한 가정에서도 다리마다 0.5틱이면 95% 구간이 전부 0 아래입니다. 시장가 주문은 호가 한 칸을 건너야 하므로(11/11 실측 삼성 1.0틱) 이 전략은 비용을 넘지 못합니다.
- **개선의 방향이 바뀜.** 「지정가로 비용 아끼기」보다 먼저 **판단을 1분봉에서 실시간 체결(초 단위)로 옮기는 것**이 필요합니다. WebSocket 시세체결을 이미 받고 있어 그대로 이어지는 개선입니다(8-2절).
- **수렴해도 손실.** 1틱(실제 호가단위)에서는 수렴 청산도 평균 −4.5만원이고 86% 가 손실입니다 — 되돌림 폭보다 호가 한 칸이 큽니다.
- **구간 차이 없음.** 괴리 확대기(9/21~10/21, 검증일 10일) 하루 평균 −41.4만원 vs 그 밖(14일) −38.6만원(비용 1틱).

- **얇은 월물은 β 가 작게 측정됨.** 같은 시기 β 가 11월물 데이터로 0.69~0.74, 12월물 데이터로 0.60~0.63. 체결이 드문 월물은 가격 반영이 늦어 함께 움직이는 정도가 작게 잡힙니다. 실행은 12월물이라 12월물 기준 β 0.59 를 유지합니다.

### 4-1. 구조 — 처음은 REST, 이후는 WebSocket

[실시간·WS]  접속키 → wss 연결 → 세션 초기화 → 구독: KA(삼성) · KA(하이닉스) · O1(주문/체결)

                ▼

                                                          REST 주문 → O1 통보로 체결 확인(늦으면 주문내역 조회)

### 4-4. API 를 쓸 때 지킨 것
- 성공 판정: HTTP 200 이어도 `errorCode`(정상코드 제외)·`msg_cd` 가 있으면 실패.
- 토큰 거절(401·EGW05x·**EGW023**): 같은 토큰으로 0.4초 뒤 다시 → 그래도 안 되면 재발급(10초에 한 번까지) → 한 번 더. 게이트웨이의 처리 전 거절이라 주문도 중복되지 않음(8-1절).
- 주문은 자동 재전송하지 않음. 분봉은 연속조회 키 대신 시각 창 둘(오전·오후)로 나눠 받음(공개 저장소 메모: 이어받기 키 신뢰 불가).
- 실시간: 웹소켓 규격 ping 프레임은 끔(켜면 국내 연결이 끊김), 서버 `pingpong` 은 받은 그대로 되돌림, 접속키는 연결마다 새로.
- 밀린 봉(마감 뒤 1봉+30초 초과)은 지표만 갱신하고 주문하지 않음(2주차 10/29 교훈).

**H2 — 아니오.** 체결 비용 69만원(거래당 약 10만원)이 판정 가격 이익 31만원의 2배가 넘었습니다. 실측 비용(삼성 1.0틱·하이닉스 0.5틱)을 과거 24일에 넣은 예상 −36.8만원/일(−40.5만~−32.0만)과 실제 −38만원이 거의 같습니다 — **하루 실행이지만 과거 검증의 비용 축 위에 정확히 놓입니다.** 비용의 대부분(62만원)은 삼성 다리이고, 그중 진입·청산이 모두 20만원 위(호가 500원)에서 일어난 6건이 대부분을 차지합니다.

**H3 — 예.** 14개 페어 주문(진입 7 · 청산 7)이 모두 두 다리 체결로 끝났고, 한쪽만 체결된 시간은 중앙 205ms(최대 550ms)로 REST 버전(6-2, 669·670ms)의 약 1/3 입니다. 체결 확인 28건이 모두 실시간 통보로 이뤄졌고, 잔고 대조 불일치는 없었습니다. 실행이 멈췄다 돌아온 상황도 주문 없이 넘겼지만, 재개 직후 데이터 공백이 지표를 왜곡한 한 건(페어 13)을 찾아 고쳤습니다.

**주문 직전 z(presend).** 진입 7건 중 4건은 판정한 지 1초 안에 z 가 줄었습니다(−2.31 → −1.93 · 3.32 → **1.17** · −2.55 → −2.28 · −2.23 → **−1.36**). 3건은 주문 전에 이미 진입 기준(±2) 안으로 돌아왔습니다. 1분봉 종가가 호가 한쪽 끝에 찍혀 신호가 나고, 다음 체결에서 곧바로 반대쪽으로 돌아가는 모습 — 과거 검증의 「체결 지연 점검」이 실시간에서 그대로 보였습니다.

**중간값으로 판단했다면? (11/11 체결 기록 재현, `pair_mid_replay.py`, 결과 `results/mid_replay_1111/`).** 실시간으로 받은 시세체결 68,686건에는 그 순간의 매수·매도 1호가가 함께 있어, 같은 엔진으로 하루를 두 가지 봉으로 다시 돌렸습니다. 체결은 봉 마감 2.5초 뒤 첫 호가에서 시장가(사면 매도호가, 팔면 매수호가)로 가정했습니다.

| 판단 기준 | 신호 | 거래 | 시장가 체결 손익 | 중간값 체결 손익(비용 0) | 체결 비용 |
| --- | --- | --- | --- | --- | --- |
| 체결가(지금 방식) | 15 | 7 | −39만원 | +9만원 | 48만원 |
| 중간값 (매수호가+매도호가)/2 | 10 | 8 | −44만원 | +4만원 | 48만원 |

- 체결가 방식 재현(−39만원)이 실제(−38만원)와 거의 같아 재현 방식은 믿을 만합니다.
- 중간값으로 판단하면 튕김에서 나온 신호가 줄지만(15 → 10), **중간값 기준으로 잰 이익도 +4만원뿐**입니다. 「판정 가격 기준 +31만원」의 대부분은 호가 튕김이었고, 1분 단위의 진짜 되돌림은 거래당 비용(삼성 반 칸 × 2 + 하이닉스 반 칸 × 2 ≈ 6만원)보다 훨씬 작습니다. 체결 지연 0.5·5초로 바꿔도 결론이 같습니다.
- 그래서 「판단만 중간값으로 바꾸기」로는 부족하고, **비용 쪽(지정가)** 이나 **되돌림 폭이 비용보다 큰 더 긴 시간 단위**로 가야 합니다(8-2절).
- 호가 차는 대부분 딱 한 칸이었습니다(삼성 20만원 이상 97% · 20만원 미만 85%, 하이닉스 93%).
- 12:36 진입 1건은 실행이 멈춘 구간에 걸쳐 청산 호가가 13:12 것으로 잡혔습니다(실제 실행에서도 같은 공백).

**실행 전 분석과의 비교.** 실행 전 분석은 「수렴 폭 21bp ≈ 왕복 비용 21bp」로 비용이 관건이라고 봤지만, 삼성 호가단위를 100원으로 잡은 잘못 때문에 비용을 약 2.6배 과소평가했습니다. 결론의 방향(비용이 결과를 정함)은 같았고, 실제로는 더 분명하게 비용을 넘지 못합니다.
